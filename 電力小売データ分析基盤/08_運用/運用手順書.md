本書は、商用運用を開始した後の日次・月次・定期の作業と、監視・障害対応・再処理・変更管理の手順を定める。本書中の章・節番号と記号（例：B-05、T-03）は、特に断りのない限り基本設計書のものを指す。

## 1. 運用体制と役割

| 役割 | 運用での責務 |
|---|---|
| 運用担当 | 日次・月次のバッチ実行の確認、監視と障害の一次対応、再処理・定期作業の実施、オンコール |
| 管理者 | 運用の最終責任。締め済み期間の再計算の承認、制度改定時の対応方針の決定 |
| 業務担当者 | マスタの登録（取引先休日、単価改定、契約変更）、日報の確認、検算 NG 時の業務面の原因調査 |
| SE | 障害の二次対応（原因の特定と修正）、変更管理での設計・ソースの改訂 |

通知先と一次対応・二次対応の体制はヒアリング F18-02 の決定に従う。

## 2. 日次運用

### 2.1 バッチスケジュール

バッチの一覧と実行時刻は [基本設計書 12.2 バッチスケジュール](../04_基本設計/基本設計書.md#122-バッチスケジュールjst) による。日報に関わる主な時刻は次のとおり。

| 時刻 | 処理 | 運用担当の確認事項 |
|---|---|---|
| 02:00 | カレンダー生成・拡張（B-11） | 失敗の通知がないこと |
| 06:00 | 前日確報取込（B-04）、06:10 訪問検針地点のプロファイル配分（B-04b） | 取込遅延の通知がないこと |
| 07:00 | 日報生成（B-05。完了目標 07:20）とアーカイブ（B-13） | バッチ実行ログに B-05 の成功が記録されていること |
| 07:20 | 検算（#1〜#3） | データ品質日次の検算結果 |
| 07:30〜08:05 | 抽出の更新と完了監視（5分間隔・最大6回） | 「本日の日報を公開」の通知。公開目標は 08:15 |
| 11:30 | JEPX価格取込（B-01） | 欠損時のリトライ結果 |

自社休業日の稼働は [基本設計書 12.5 自社休業日のバッチ稼働制御](../04_基本設計/基本設計書.md#125-自社休業日のバッチ稼働制御) に従い、休業日の日報は翌営業日に確認する。

### 2.2 日報の公開までの確認手順

公開の仕組みは [詳細設計書 第4部 1. 分析画面抽出同期・完了監視](../05_詳細設計/詳細設計書.md#1-bi抽出同期完了監視プロシージャのロジック詳細仕様) による。

1. 検算が通過し、公開可否が「公開」になったことを通知で確認する。
2. 「検算未通過で遮断」の場合は、公開されないまま前日までの画面が表示される。本書 3 の検算NG の手順で原因を調べ、修正後に日報を再生成して抽出を手動で更新する。
3. 「抽出未検知」が6回続いた場合（同期遅延警告）は、バッチの完了を確認したうえで、抽出データソースを手動で更新し、完了を確認してから公開を通知する。

## 3. 監視・アラートと一次対応

監視項目と条件は [基本設計書 15.4 監視・アラート](../04_基本設計/基本設計書.md#154-監視アラート) による。一次対応は次のとおり。

| 監視項目 | 一次対応 | 二次対応・エスカレーション |
|---|---|---|
| 取込遅延 | 送信元の配信状況を確認し、到着後に取込を再実行する | 30分を超えて解消しない場合は SE |
| 欠番・補完率 | 補完の件数と対象地点を確認し、需給担当へ共有する | 閾値超過が続く場合は SE |
| 単価NULL | 日報は公開停止となる。未登録の単価を業務担当者に登録してもらい、日報を再生成する | 管理者 |
| 検算NG | 経理・業務担当者と NG の種類（電力量・金額・単価網羅）を確認し、原因のデータを修正して日報を再生成する | SE（ロジックの誤りが疑われる場合） |
| 燃調未登録 | 料金担当に公表期限までの登録を依頼する | 管理者 |
| 確定値到着遅延 | 一送の開示状況を確認する。確定値の到着後に月次確定取込（B-07）を実行する | 需給担当 |
| 予測精度悪化 | 需給担当へ通知し、休日の登録漏れを疑う | 営業・カスタマーサポート |
| 顧客休日の登録漏れ疑い | 営業・カスタマーサポートへ顧客への確認を依頼する（ヒアリング F04-01 のエスカレーション手順） | 管理者 |
| 取引先休日の登録鮮度 | 総務・営業へ翌年度（翌年）分の登録を依頼する | 管理者 |
| 祝日CSV 受入不可 | マスタは前回成功時の状態のまま。次回の取込（B-10）までに配信形式を手動で確認し、受入条件の閾値の調整または手動登録を行う | SE（緊急） |
| Cold 未退避パーティション | 本書 5.3 のアーカイブ処理を手動で実行し、件数の一致を確認する | SE |
| 実量制の欠損月 | 料金担当へ通知し、欠損月の実績の取得を依頼する | 管理者 |
| バッチ失敗 | バッチ実行ログで失敗箇所を確認し、原因を取り除いて再実行する。日報バッチはべき等なので再実行してよい | SE |

## 4. 月次運用

| 作業 | 時期 | 手順 |
|---|---|---|
| 月次確定取込（B-07） | 一送の N 営業日目（営業日カウンター） | 取込後、確定値受領状況を確認する |
| 月次リラン（B-08） | B-07 完了後（JEPX 月次精算書の受領後） | 確定値で対象月を再計算し、差異レポートを確認する。定額手数料の精算差額は月末日に一括計上される |
| BG 月次精算（B-08b） | B-08 完了後 | 代表者の通知額と突合する |
| 確定A値取込・FIP 再計算（B-09b） | 毎月25日頃 | 当月の FIP 収支が確定A値で再計算されたことを確認する |
| 請求突合 | 月次 | 請求丸め調整を含めて1円単位の一致を確認する（検算 #2） |
| 締め済み期間の再計算 | 都度 | 管理者の承認を得てから実行し、監査ログを残す（ヒアリング F15-03 の承認フローに従う） |

## 5. 定期作業

### 5.1 祝日の取込

毎月1日・15日 03:00 に祝日CSV を自動取込する（B-10）。受入不可の通知があった場合は本書 3 の手順で対応する。

### 5.2 取引先休日の棚卸し

年1回と都度、自社の約款休日（総務の確定後）と顧客の会社休日（営業・カスタマーサポート経由）を登録する。登録の責任者と承認はヒアリング F04-01 の決定に従う。

### 5.3 コマ別集約マートのアーカイブ

日報バッチ（B-05）の末尾で、境界日（今日 − 2年）のパーティションを現用（`agg_slot_summary_active`）から長期（`agg_slot_summary_cold`）へ複製する。処理は [ソースコード説明](../06_ソースコード/ソースコード説明.md) の運用スクリプト `b13_archive_slot_summary.sh` で行う。

- 環境変数 `GCP_PROJECT_ID`、`BQ_DATASET_GOLD` を設定して実行する。
- 境界日のパーティションが現用側にない場合、または長期側と件数が一致している場合は、何もせずに終了する。
- 長期側に部分的な複製が残っている場合は、そのパーティションを削除してから複製し直す。
- 現用側は削除しない（パーティションの有効期限 737 日で自動削除される）。
- 複製結果の件数一致は、翌日の「Cold 未退避パーティション」監視で再確認される。

### 5.4 年次の制度確認

年度ごとに次の公表値を確認し、期間管理マスタへ登録する。

| 対象 | 確認内容 | 関連 |
|---|---|---|
| 容量拠出金 | 容量市場の精算仕様（ピーク時 kW 按分への移行、年度別単価の改定）。変更時は予備の単価列を有効化する | ヒアリング F03-03 |
| FIP バランシングコスト | 年度別単価（基本部分と激変緩和の上乗せ、上乗せの終了年度） | ヒアリング F03-04 |
| 再エネ賦課金 | 新年度の単価（5月検針分から適用） | ヒアリング F03-09 |
| 託送料金・送電損失率 | 約款の改定 | ヒアリング F03-01・F03-02 |

## 6. 再処理（バックフィル）手順

1. Bronze に原本があることを `file_hash` で確認する。
2. stg で対象期間の Silver を Bronze から再構築し、旧 Silver との差分を出す。
3. 差分が想定どおりなら prod で対象パーティションを再構築する。
4. Gold（`agg_*`）を対象期間で再実行する（第11章のべき等性により安全）。
5. 締め済み期間が含まれる場合は承認と監査ログを必須とする。

## 7. 訂正・更正の扱い

| 対象 | 扱い |
|---|---|
| 実績の訂正（一送からの計量値の訂正） | 元のレコードを残し、打ち消しと差分のレコードを追記する。確定値は上書きしない |
| 単価の更正（インバランス単価など） | 単価を上書きし、影響日の日報・インバランス日次・BG 精算を再計算する（B-08c） |
| 期間管理マスタの改定 | 新しい期間のレコードを追加し、旧レコードの終了日を閉じる。変更は承認ワークフロー経由に限る |

詳細は [基本設計書 12.4 確定後の修正](../04_基本設計/基本設計書.md#124-確定後の修正) による。

## 8. 変更管理

- **制度改定**（容量拠出金の方式、発電側課金の割引、賦課金単価、FIP の経過措置など）があった場合は、[ヒアリングシート兼適合分析表](../03_要件定義/ヒアリングシート兼適合分析表.md) の該当項目を再確認し、GAP があれば対策を決めてから、基本設計書 → 詳細設計書 → ソースコードの順に改訂する。基本知識の講義（初級・上級・応用）の該当項目も併せて更新する。
- **スキーマ変更**は [基本設計書 15.6 スキーマ変更](../04_基本設計/基本設計書.md#156-スキーマ変更) に従い、dev → stg → prod の順に適用する。
- **新たな失敗事例**が出た場合は、[講義 応用 実務の落とし穴](../01_基本知識/05_講義_応用_実務の落とし穴.md) に追加し、現場の経験を積み上げる台帳として運用する。
