本書は、本基盤のソースコード（SQL と運用スクリプト）の構成と、各ファイルの根拠となる設計を示す。ソースコードは詳細設計書を入力として実装する。詳細設計書と差異がある場合は詳細設計書を正とし、ソースコードを修正する。

## 1. 構成

```
06_ソースコード/
  sql/
    ddl/        masters.sql / facts.sql / marts.sql      マスタ・ファクト・集計マートのテーブル定義
                scd2_validation_customer_contracts.sql    契約履歴の重複・隙間・逆転の検証クエリ
    function/   udf_validate_demand_point_number.sql       供給地点特定番号の先頭3桁の検証関数
    view/       実績時系列統合、料金用休日、実量kW判定、市場連動単価解決、利益階層、分析画面抽出
    procedure/  日報損益、検算、BG按分、祝日取込、訪問検針プロファイル配分、予測精度、抽出完了監視、契約移行ゲート
  ops/          b13_archive_slot_summary.sh                コマ別集約マートのアーカイブ（現用→長期）
  ソースコード説明.md（本書）、規約適合状況.md
```

配備の順序は、テーブル定義 → 関数 → ビュー → プロシージャとする。

## 3. テンプレート変数

SQL にはプロジェクト名・データセット名を直接書かず、次のテンプレート変数を使う。配備時に CI/CD で環境別の値へ展開する（未展開のまま実行してはならない）。

| 層 | 変数 | 本番での展開例 |
|---|---|---|
| 共通 | `${GCP_PROJECT_ID}` | 本番プロジェクトID |
| 生データ層（Bronze） | `${BQ_DATASET_BRONZE}` | `bronze_power` |
| 事実ファクト層（Silver） | `${BQ_DATASET_SILVER}` | `silver_power` |
| 集計マート層（Gold） | `${BQ_DATASET_GOLD}` | `gold_power_mart` |
| ステージング | `${BQ_DATASET_STAGING}` | `staging_power` |

## 4. 監査列

ファクトと集計マートの全テーブルは、次の3列を持つ。全プロシージャは引数 `p_run_id`・`p_pipeline_version` を受け取り、`INSERT`／`MERGE` でこの3列を設定する。プロシージャ間の `CALL` にも引数を引き継ぐ。

| 列 | 設定する値 |
|---|---|
| `ingestion_run_id` | 複数ジョブをまたいで一意な実行ID（Workflows の実行ID など）。オーケストレータから渡す。BigQuery のジョブIDは入れない |
| `loaded_at` | 各文の `CURRENT_TIMESTAMP()`（UTC） |
| `pipeline_version` | CI/CD が配備時に注入した処理コードの版。SQL 本文にリテラルで書かない |

## 5. 実装上の約束

- テーブル定義は `CREATE TABLE IF NOT EXISTS` とし、本番で `CREATE OR REPLACE TABLE` を使わない（ビュー・プロシージャの `CREATE OR REPLACE` は対象外）。
- 大規模な時間系テーブルは対象実需給日でパーティションし、パーティション指定を必須にする。
- 列・テーブルの説明は `OPTIONS(description = ...)` で設定する。
- 真偽値は `BOOL`、金額・電力量は `NUMERIC` とし、`FLOAT64` を使わない。
- 規約への適合状況は [規約適合状況](規約適合状況.md) に示す。
