## 1. 目的

[機能一覧](../02_製品機能/機能一覧.md) の標準機能ごとに、導入先の業務・制度・契約を確認し、標準機能との適合を判定する。GAP があれば、影響範囲と改修提案をまとめて対策を決める。ここで決まった内容が、以降の設計（基本設計・詳細設計）の入力になる。

## 2. 進め方

| 手順 | 内容 | 主担当 |
|---|---|---|
| 1. 準備 | 機能一覧と本表を導入先へ事前に送り、回答者（部署）を割り当てる | PM・コンサルタント |
| 2. ヒアリング | 機能ごとに「標準機能の内容」を説明し、「確認事項」を質問して回答を記入する | コンサルタント（回答：業務担当者） |
| 3. 判定 | 回答をもとに、項目ごとに適合／条件付き適合／GAP／対象外を判定する | コンサルタント |
| 4. GAP 分析 | GAP の項目について、影響範囲（機能・データ）と改修提案、影響度を記入する | SE |
| 5. 対策の決定 | 改修提案を採用するか、運用で回避するかを決め、決定内容・根拠資料・決定日・決定者を記録する | 管理者（投資を伴うものは経営者） |
| 6. 完了 | 全項目が「決定済み」になったことを確認し、要件定義を完了する | PM |

**合意の記録方法**：各項目について「決定内容・根拠資料・決定日・決定者」を残す。決定が変わった場合は、影響するマスタ・バッチ・再計算の対象期間を明記して変更管理に載せる。

## 3. 判定の基準

| 判定 | 意味 |
|---|---|
| 適合 | 標準機能のまま使える |
| 条件付き適合 | 設定（マスタ・パラメータの登録）で吸収できる |
| GAP | 標準機能では対応できず、改修または運用での回避が必要 |
| 対象外 | 導入先の業務に該当しない |

**対策区分**

| 区分 | 内容 | 影響する工程の目安 |
|---|---|---|
| 設定 | パラメータ・区分値の登録で吸収する | 導入（初期データ） |
| マスタ追加 | マスタの行・区分を追加して吸収する | 導入（初期データ）、運用（マスタ保守） |
| ロジック改修 | 計算・判定・データ構造を変える | 基本設計・詳細設計・ソースコード・導入・運用のすべて |
| 運用で回避 | システムは変えず、業務手順で吸収する | 運用 |

**影響度**：大（複数機能・データ構造に及ぶ、または過去データの再計算が必要）／中（1機能内の計算・判定の変更）／小（設定・マスタ登録で済む）。

**影響範囲の書き方**：影響する機能ID と、影響するデータ（機能一覧の「主なデータ」の論理名）を記入する。設計書の各章は対応する機能ID を持つため、機能ID から影響する設計箇所を特定できる。

## 6. 要件定義の完了条件

- 全項目の判定が記入され、GAP の項目はすべて対策（改修または運用で回避）が決定済みであること。
- 制度確認の項目は、一次情報（約款・規程・公表資料）で確認した結果が記入されていること。未確認の項目が残る場合は、その項目に依存する作業と検算を特定し、確認後に再実行する計画を立てること。
- 業務決定の項目は、決定内容・根拠資料・決定日・決定者が記録されていること。
