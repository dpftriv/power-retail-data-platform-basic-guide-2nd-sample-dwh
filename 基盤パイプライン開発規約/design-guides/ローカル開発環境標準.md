# ローカル開発環境標準

**版**：1.0

**適用対象**：データ基盤汎用デザインガイド、電力小売りデータ基盤個別ガイド、Terraform / BigQuery / CI/CD実装

## 1. 標準ツール一覧

| ソフト | 推奨バージョン | 必須度 | 用途 |
|---|---:|---|---|
| **Terraform** | **1.16.2** | 必須 | GCP IaC |
| **Python** | **3.13.x** | 必須 | Cloud Functions / スクリプト |
| **Google Cloud SDK** | **583.0.0** | 必須 | `gcloud` / `gsutil` / `bq` |
| **Git** | **2.4x～2.5x** | 必須 | ソース管理 |
| **GitHub CLI** | **2.x** | 推奨 | GitHub操作 |
| **jq** | **1.7.x** | 推奨 | JSON処理 |
| **yq** | **4.x** | 推奨 | YAML処理 |
| **curl** | Ubuntu標準 | 必須 | API / HTTP通信 |
| **wget** | Ubuntu標準 | 推奨 | ダウンロード |
| **unzip** | Ubuntu標準 | 必須 | Terraform等の展開 |
| **make** | 4.x | 推奨 | ビルド / 自動化 |
| **Docker** | 28.x～29.x系 | 推奨 | コンテナビルド |
| **Docker Compose** | v2.x | 推奨 | ローカル環境 |
| **Node.js** | 22 LTS | 条件付き | Node.js系Cloud Functions等 |
| **OpenSSL** | Ubuntu標準 | 必須 | TLS / 証明書 |
| **bash** | Ubuntu標準 | 必須 | シェルスクリプト |

## 2. 適用ルール

開発者のローカル環境は、上表の推奨バージョンを基準にする。CI/CDでは、Terraform、Python、Google Cloud SDK、Checkov、ConftestのバージョンをWorkflowまたは専用設定ファイルで固定し、ローカルとCIの差異をPull Requestで検知する。

Terraformのバージョンは`1.16.2`を標準とし、リポジトリ直下の`.terraform-version`で固定する。Terraform ProviderのバージョンはTerraform本体とは別に`required_providers`で固定する。

Pythonは`3.13.x`を標準とし、Checkovおよび補助スクリプトの実行にはプロジェクト単位の仮想環境を使用する。Cloud Functionsのランタイムは、対象サービスで利用可能なPython 3.13ランタイムと一致させる。

Google Cloud SDKは`583.0.0`を基準とする。`gcloud`、`bq`、`gsutil`の実体が同一SDKに含まれることを確認し、複数のSDKインストールをPATHへ混在させない。

Git、GitHub CLI、jq、yq、Docker、Node.jsは用途に応じて導入する。必須でないツールをCIへ追加する場合は、利用目的、バージョン、脆弱性対応、ライセンスをREADMEまたはツール台帳へ記録する。

## 3. 確認コマンド

```bash
terraform version
python3 --version
gcloud version
git --version
gh --version
jq --version
yq --version
curl --version
wget --version
unzip -v | head -1
make --version
docker --version
docker compose version
node --version
openssl version
bash --version
```

CIで確認する場合は、実行ログに資格情報、OIDCトークン、Secret、PIIを出力しない。

## 4. リポジトリでの固定ファイル例

```text
.terraform-version
.python-version
.tool-versions              # asdfを採用する場合
mise.toml                   # miseを採用する場合
requirements-dev.txt
package.json                # Node.js系を使用する場合
```

利用するバージョン管理ツールはプロジェクトで一つに統一する。複数の管理ファイルを置く場合は、相互に異なるバージョンを指定しない。

## 5. 互換性と更新

推奨バージョンを更新する場合は、Terraform plan、Conftest、Checkov、SQL静的検査、BigQuery dry run、Stagingアクセス検証を再実行する。Google Cloud SDK、Terraform Provider、Checkovは、認証、API仕様、plan JSON、Policy評価に影響する可能性があるため、単独で更新せず、変更理由と検証結果をPull Requestへ記録する。

OS標準と記載したツールは、Ubuntuの標準パッケージを使用する。Ubuntuのリリースによって実際のパッチ番号が異なる場合は、セキュリティ更新を適用した最新パッケージを使用し、コマンドの互換性を検証する。
